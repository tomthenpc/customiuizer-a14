## 核心变更

### 1. `check_status_bar_display_registry_prune`

- 提取 `prune()` 函数体，避免缺失 `prune()` 时提前 `return` 导致 `bind()` 检查被跳过。
- 验证 `byDisplay` 遍历循环中：
  - `state.registrations.cleanupAll()`
  - `state.generation?.get() == null`
  - `state.registrations.size == 0`
  - `deadDisplays.add(displayId)`
- 验证 `byDisplay.remove()` 必须在循环外，且位于 dead list 构建之后。
- 验证 `val clearedStates = pendingByOwner.expunge()` 被保留并遍历，每个 cleared state 调用 `registrations.cleanupAll()`。

### 2. `_check_left_icon_handle`

- 在 `check_status_bar_registration_cleanup` 中新增结构检查，取代原来的 token 匹配：
  - 读取旧 `leftIconRegistrationHandle`；
  - 在 `oldHandle != null` 分支调用 `oldHandle.cleanupNow()`；
  - `oldHandle.cleanupNow()` 必须出现在新的 `addIconGroup()` 之前；
  - `addIconGroup` 后注册 `state.registrations.register(mStatusBar)`；
  - cleanup lambda 必须 `releaseRegistrationSilently` 同个 controller 与 manager；
  - 新 handle 必须保存到 `leftIconRegistrationHandle`。
- 仍允许 `oldHandle == null` 分支对历史 `staleManager` 做兼容 fallback release。

### 3. `check_module_helper_fatal_boundaries`

- 移除前置 `catch(OutOfMemoryError)` 对后续 `catch(Throwable)` 的“保护”。
- 要求每个 generic catch 函数体开头即 `throw variable` 或 `FatalErrors.unwrapAndRethrowIfFatal(variable)`。
- 支持 `val x = FatalErrors.unwrapAndRethrowIfFatal(t)` 的赋值包裹形式。
