## What changed

- Added `WeakIdentityMap.kt` to replace `java.util.WeakHashMap` in `StatusBarDisplayRegistry` pending bucket. Uses `System.identityHashCode`, `WeakReference` keys and a `ReferenceQueue` for cleanup. No permanent background thread.
- Rewrote `StatusBarDisplayRegistry.kt` with `WeakIdentityMap`, `detach(owner)`, `expunge()`, and `allStatesSnapshot()`. Network-speed reads now happen on the main thread via an immutable snapshot.
- Added `StatusBarNetworkSpeedDispatcher.kt`: a pure, testable object that drops stale sequence numbers and applies the immutable payload through an applier function.
- Moved `SystemUIStatusBarHooks` network-speed posting to `netSpeedMainHandler.post { StatusBarNetworkSpeedDispatcher.dispatch(...) }`, removing stale `row/owner/state` captures.
- Added `installStatusBarViewLifecycleHook` for `MiuiPhoneStatusBarView.onDetachedFromWindow` to release per-owner state and prune from the main looper.
- Wired `StatusBarDisplayRegistry.onPendingChanged` to schedule `statusBarPendingPruneRunnable` with a 250ms delay; no permanent background polling.
- Hardened `ModuleHelper.getCPUThermalId` fatal boundary and split `scanForCpuThermalId` for testability. State is only written after a non-fatal full scan.
- Updated `tools/check-invariants.py` to enforce `WeakIdentityMap`, `detach`/`expunge`/`allStatesSnapshot`, and network-speed dispatcher rules.
- Updated `tools/tests/test_status_bar_registration_invariants.py` with R3 counterexamples.
