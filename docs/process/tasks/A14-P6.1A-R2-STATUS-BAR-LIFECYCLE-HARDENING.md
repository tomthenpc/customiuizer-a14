# A14-P6.1A-R2 Status bar lifecycle hardening

## Goal

Strengthen the per-display status bar registration lifecycle so that:
- weak owner cleanup runs after the owner is garbage collected;
- dead display and pending states release their registrations before pruning;
- static invariants detect the R2 failure modes without false negatives;
- `ModuleHelper` silent reflection helpers and adjacent `catch(Throwable)` blocks propagate fatal errors.

## Acceptance

- [ ] `OwnedRegistrations.register` takes a no-argument `() -> Unit` cleanup.
- [ ] `OwnedRegistrations` runs cleanup even when the owner is null / GCed.
- [ ] `StatusBarDisplayRegistry` pending state is reachable and cleanable after owner GC.
- [ ] `StatusBarDisplayRegistry.prune` calls `cleanupAll` before removing dead states.
- [ ] `SystemUIStatusBarHooks` cleanup closures do not capture the owner.
- [ ] `netSpeedSecondRowHookCallback` re-reads row/owner/state in the posted runnable.
- [ ] `ModuleHelper` `catch(Throwable)` blocks call `FatalErrors.unwrapAndRethrowIfFatal(t)` first.
- [ ] `tools/check-invariants.py` passes with zero violations on current code.
- [ ] Python invariant tests pass (>= 25 counterexamples / passing rewrites).
- [ ] Kotlin unit tests pass (`:app:testDebugUnitTest`).
- [ ] `scripts/verify.ps1 -Mode Fast` passes.
- [ ] `TASK_STATE.md` and handoff updated.
