## 必须修复

### 1. 纯叙述文字不能作为 evidence_commands

以下属于无效证据：

```text
docs/progress/A14_PROGRESS_CURRENT.json 与 .md 已重新生成
P12.1 文档已经验证
```

合法命令必须来自 fenced command block 或明确的 `Evidence commands:` 字段，并以允许的可执行程序开头，例如：

```text
python
python3
py
powershell
pwsh
.\gradlew.bat
./gradlew
gradlew
git
gh
adb
java
```

解析阶段不执行命令，只检查结构。普通中英文叙述不能进入 `evidence_commands`。

### 2. evidence_paths 必须是真实仓库路径

合法路径必须：

```text
明确标记为路径
仓库相对路径
不能通过 .. 逃出仓库
文件/目录真实存在，或受支持 glob 至少匹配一项
不能是一整句叙述
```

### 3. evidence_level 不能由 State 直接映射

分离：

```text
declared_state
evidence_level
scoring eligibility
```

语义：

```text
pending:
  没有有效 path/command/commit

partial:
  有有效 path 或 command，但没有有效 evidence commit

verified:
  至少有一个有效 path 或 command，并且有有效 evidence commit
```

禁止通过 `state.lower()` 生成 evidence_level。

### 4. evidence_commit 必须来自机械来源

只从当前任务段或已经验证的 evidence 文档中的结构字段解析：

```text
EvidenceCommit:
QualifyingCommit:
EngineeringCommit:
Commit:
Baseline commit:
BaseCommit:
```

要求：

```text
7–40 位 SHA 必须能被 git rev-parse 唯一解析
最终保存完整 40 位 SHA
git cat-file -e <sha>^{commit} 成功
该 commit 是 HEAD 的 ancestor
不能从普通叙述中随便抓 SHA
不能用当前 HEAD 给所有项目统一充当 evidence commit
```

### 5. COMPLETE / VERIFIED_* 无有效 provenance 时不得获得完成分

规则：

```text
TODO / BLOCKED_EXTERNAL:
  保持现有逻辑

COMPLETE / VERIFIED_*:
  只有 evidence_level == verified 时才允许正常 state factor

否则:
  进入 evidence_pending bucket
  不得获得 verified/complete 得分
```

不要发明未记录的折中分数。历史进度下降可以接受，不能为了维持百分比伪造证据。

### 6. P12 权重必须按计划四项固定分配

```text
EXPECTED_P12_IDS = P12.1, P12.2, P12.3, P12.4
5.0 / 4 = 1.25 each
```

删除任一子项时：

```text
其余子项仍为 1.25
验证因缺失子项失败
不能自动重均分为 1.67
```
