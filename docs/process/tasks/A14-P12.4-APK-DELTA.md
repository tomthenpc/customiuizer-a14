
## 阶段二：独立 delta generator

新增 `tools/apk_size_delta.py`。

输入：

- `docs/performance/A14_APK_SIZE_BASELINE.json`
- `docs/performance/A14_APK_SIZE_CURRENT.json`
- `docs/performance/A14_APK_SIZE_BASELINE_DEVELOP.json`
- `docs/performance/A14_APK_SIZE_CURRENT_DEVELOP.json`
- `BaselineCommit`
- `CurrentSourceCommit`
- `app/build.gradle.kts`

输出：

- `docs/performance/A14_APK_SIZE_DELTA.json`
- `docs/performance/A14_APK_SIZE_DELTA.md`

工具必须从 `app/build.gradle.kts` 机械提取并记录：

```text
versionCode
versionName
applicationId
minSdk
targetSdk
ABI
```

当前构建配置中的版本值必须以源码为准，不能硬编码到测试中。

Delta 至少包含所有指定字段的 `baseline` / `current` / `delta bytes` / `delta percent` / `increase/decrease/unchanged`。

同时生成 ZIP entry 级别差异：`added` / `removed` / `changed`，以及 top 20 compressed-size `increases` / `decreases`。

每个当前 APK 必须记录：

```text
source commit
variant
versionName
versionCode
SHA-256
APK bytes
relative artifact path
```

报告必须明确区分：

- Debug：未压缩、未 R8 的开发诊断产物
- Develop：R8 + resource shrinking，unsigned，更接近正式 APK 体积，但不等同于正式签名 Release

不得因为 APK 变小就宣称性能提高，也不得因为变大就直接宣称性能回退；必须依据 dex/resource/lib 等具体 bucket 解释变化。
